# 失敗時はallowlistした分類のみ表示し、詳細はLogsへ

dedupeはサイレント。LLM/OpenRouter失敗時はスレッドへ通常メッセージ（ephemeralではない）で通知するが、表示するのはこちらで定義した安定した分類とHTTP statusだけに限る。上流の生のエラーメッセージはスレッドに出さず、Workers Logs（ADR 0018）に出す。

```
生成に失敗しました（rate_limited / HTTP 429）。少し待って同じスレッドで再送してください。
```

当初は「429/5xxの詳細なcode/messageをそのまま表示し、含まれる検索キーワードと画像URLをマスクする」と決めていたが、以下の理由で方式を反転した。

## denylistを採らない理由

- **列挙しきれない**: OpenRouterや上流プロバイダの4xxはリクエスト内容をエコーバックすることがあり（バリデーションエラーでプロンプトが返る等）、「検索キーワードと画像URL」の列挙では捕まえられない
- **脅威モデルが逆だった**: 当初の理由は「DM誰でも可なので漏えいを防ぐ」だったが、DMの参加者は本人とボットだけで漏れる相手がいない。実際に危ないのはチャンネルのスレッドで、他人の入力を含むエラーが参加者全員に公開投稿されるケースである
- **文面が常にノイズを含む**: 「[検索キーワード省略] / [画像URL省略]」が検索も画像も関与しない429でも毎回表示されていた

## Consequences

透明性（どのモデルがどう失敗したか）はスレッドからは失われる。ADR 0018 で観測をWorkers Logsのみと決めているため、詳細を追う導線は `bun run logs` に一本化される。
